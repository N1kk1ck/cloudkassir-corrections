# Формат входных данных

Обе таблицы принимаются как CSV (UTF-8, в том числе BOM) или XLSX. CSV-разделитель
определяется среди запятой, точки с запятой и табуляции. XLSX читается из
единственного видимого листа или из явно указанного листа. Скрытые pivot-cache
не используются. Формулы должны иметь сохранённые значения; предпочтительны
таблицы со значениями без формул. Идентификаторы храните как текст, особенно
длинные номера: округление, уже сделанное Excel, восстановить нельзя.

## Список чеков

| Поле | Обязательно | Содержание |
| --- | --- | --- |
| entity_id | да | Стабильный ключ из organizations |
| receipt_id | да | Уникальный в организации идентификатор отдельной операции |
| order_id | да | Номер заказа для связи с составом |
| receipt_type | да | income или income_return |
| amount | да | Положительная итоговая сумма чека, до двух знаков |
| currency | да | RUB |
| status | да | completed или paid |
| email | email или phone | Контакт покупателя |
| phone | email или phone | Телефон, например +79990000000 |
| items_confirmed | для возврата | true после проверки именно возвращаемых позиций |

receipt_id нельзя переназначать, менять после отправки или начинать нумеровать
заново каждый месяц. Одна пара entity_id + receipt_id обозначает одну операцию.
Возврат получает собственный receipt_id; сумма возврата тоже положительная.
Если поступление и возврат имеют разные составы, используйте разные order_id
либо явно задайте receipt_id каждой позиции.

## Состав чеков

| Поле | Обязательно | Содержание |
| --- | --- | --- |
| entity_id | да | Организация, как в списке чеков |
| order_id | да | Номер заказа |
| receipt_id | при нескольких чеках на заказ | Ограничивает позицию конкретным чеком |
| line_id | да | Уникальный номер строки внутри заказа/чека |
| name | да | Название позиции, 1–128 символов |
| quantity | да | Положительное количество, до двух знаков |
| price | да | Цена единицы до скидки, неотрицательная, до двух знаков |
| amount | да | Итог позиции после скидки, неотрицательный, до двух знаков |
| vat | нет | Код НДС; по умолчанию из fiscal.vat; текст null — без НДС |
| object | нет | Признак предмета расчёта 1–13; по умолчанию из организации |

Сумма amount всех позиций должна совпасть с amount чека точно, без допуска
в одну копейку. Сумма позиции не должна превышать округлённое quantity × price.
Количество не подменяется единицей при отсутствии. Отрицательные значения,
NaN и Infinity не принимаются.

Доставка включается самостоятельной позицией, обычно с object=4. Конкретные
фискальные признаки выбирает пользователь под свою кассу.

Если на один заказ приходится несколько оплат, передайте отдельные позиции
с receipt_id для каждой. Смешивать для одного чека состав заказа без receipt_id
и состав с receipt_id нельзя. Неподтверждённый состав или неоднозначная связь
попадут в review. Повторы ключей таблиц блокируют обработку целиком.
Неиспользованные строки учитываются в summary; сюда входят также позиции
чеков, не прошедших проверку.

## Соответствие колонок и значений

Пример config/mapping.example.yaml показывает два независимых раздела:
receipts и items. Для каждого можно задать:

- sheet — имя листа XLSX; в CSV не используется;
- header_row — номер строки заголовков, начиная с 1;
- columns — стандартное поле слева, название колонки выгрузки справа;
- values — явный перевод значений выбранного стандартного поля.

~~~yaml
receipts:
  sheet: "Оплаты"
  header_row: 3
  columns:
    entity_id: "Компания"
    receipt_id: "Номер операции"
    order_id: "Номер заказа"
    receipt_type: "Операция"
    amount: "Итого"
    currency: "Валюта"
    status: "Статус"
    phone: "Телефон"
  values:
    entity_id:
      "ООО Пример": "my_company"
    receipt_type:
      "Оплата": "income"
      "Возврат": "income_return"
    status:
      "Успешно": "completed"
items:
  sheet: "Позиции"
  columns:
    entity_id: "Компания"
    order_id: "Номер заказа"
    line_id: "Номер строки"
    name: "Наименование"
    quantity: "Количество"
    price: "Цена"
    amount: "Итого со скидкой"
  values:
    entity_id:
      "ООО Пример": "my_company"
~~~

Неизвестные значения не заменяются автоматически. Их проверит общий валидатор.
Одно исходное поле нельзя назначать нескольким стандартным полям.
Сопоставление колонок не вычисляет скидки, НДС, возвраты или основания коррекции.
