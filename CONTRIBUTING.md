# Участие в разработке

Организации и адаптеры входных таблиц должны задаваться конфигурацией.
Не добавляйте в код реальные названия компаний, ИНН, доступы, идентификаторы
операций, производственные суммы или пути с компьютера разработчика.

Создавайте виртуальное окружение, устанавливайте requirements.txt и запускайте:

~~~sh
python -B -m unittest discover -s tests -v
python -m pip wheel --no-deps . --wheel-dir dist
~~~

При изменении формата добавляйте обезличенный пример и проверку ошибок.
При изменении отправителя проверяйте сбои до запроса и после возможного принятия,
повторный запуск процесса, неизменность идентификаторов и работу SQLite.
Сетевые интеграционные тесты не должны запускаться автоматически.

Не включайте в issue, PR или скриншот исходные таблицы, конфигурацию с доступами,
реальный preview или базу отправок. Для воспроизведения сделайте минимальный
синтетический пример.

Перед массовым форматированием или рефакторингом отделяйте изменения поведения.
В описании PR указывайте проблему, новое поведение и выполненные проверки.
