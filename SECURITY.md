# Рабочие данные и безопасность

Public ID и API Secret не должны попадать в репозиторий, отчёты или переписку.
Используйте локальный config/organizations.yaml или переменные окружения.
Обработчик ошибок YAML не выводит исходные строки конфигурации.

Чеки и preview могут содержать персональные данные покупателей и фискальные
реквизиты. Все файлы input, output и runtime являются локальными рабочими данными.
Веб-загрузки сохраняются в runtime/uploads, в том числе конфигурации с доступами.
Не размещайте папку приложения на общедоступном сетевом ресурсе.

Приложение предназначено для локального запуска. Не публикуйте Flask-сервер
в интернете и не меняйте адрес привязки на 0.0.0.0 без отдельной разработки
аутентификации, разграничения доступа и хранения секретов.

Git не является резервной копией рабочего журнала.
После потери runtime/state.db не создавайте новый журнал для продолжения
отправок: сначала нужна сверка уже выполненных операций.

Сообщая об уязвимости, не публикуйте реальные ключи или данные покупателей.
До открытия публичного репозитория владелец должен выбрать приватный канал
для сообщений об уязвимостях; такой канал пока не настроен.
